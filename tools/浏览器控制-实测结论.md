# 浏览器 / 电脑控制 —— 实测结论

全部在一台 Windows 机器上实测过,不是推测。

## 一、能做什么(已验证)

| 能力 | 验证方式与结果 |
| --- | --- |
| 看屏幕 | PowerShell `Graphics.CopyFromScreen` 全桌面截图,约 0.5s;Python `PIL.ImageGrab` 同样可用 |
| 控制浏览器 | Node 内置 WebSocket 直连 CDP,无需 Puppeteer/Playwright。实测:打开 B站 → 聚焦搜索框 → 真键盘输入关键词 → 回车 → 进入搜索结果页,读到 95 个视频链接 |
| 读页面状态 | CDP `Runtime.evaluate` 读标题/URL/DOM/登录态,比截图盲点坐标可靠得多 |
| 页面截图 | CDP `Page.captureScreenshot`,拿整页图不依赖窗口是否在前台 |
| 控制任意程序 | `pyautogui`:屏幕坐标点击 + 键盘输入。实测在记事本里成功打进一行字 |
| 读窗口与控件 | Windows UI Automation(`UIAutomationClient` 程序集)能列出真实窗口并读到窗口标题 |
| 底层 Win32 | PowerShell 为 FullLanguage,`Add-Type` + P/Invoke 可用(user32 实测通过) |

环境现成:Node、Python、Chrome、Edge、`pyautogui`、`PIL`。
**没装** `playwright` / `selenium` / `mss` / `pywinauto`,但都不需要。

## 二、四个真实约束(踩过才知道)

1. **带调试端口的 Chrome 必须由人在沙箱外启动。**
   沙箱内启动 Chrome 会因为 crashpad 被拒而自杀(`0x5 OpenProcess 拒绝访问` → `crash handler failed to launch, self-terminating`,退出码 `4294930433`)。加 `--no-sandbox --disable-breakpad` 也无效。
   → 解决办法:`tools\打开可控制浏览器.ps1` 由人双击运行。启动之后 agent 就能长期控制这个浏览器。

2. **Node 的管道式 `spawn` 在沙箱里必然 `EPERM`。**
   这是 DSH 沙箱的既定边界,不是脚本写错。用 `stdio: 'ignore'` 或改用 PowerShell `Start-Process`。

3. **`.ps1` 文件被执行策略禁止直接运行**(Windows PowerShell 5.1,且无 `pwsh`)。
   必须 `powershell -NoProfile -ExecutionPolicy Bypass -File xxx.ps1`。

4. **OS 级键盘输入会被输入法吃掉。**
   实测 `pyautogui.write('agent typed this with OS-level keyboard')` 在中文 IME 下变成
   `阿根廷typedthiswithOS-levelkeyboard`(首字母触发候选词)。要输入中文,走 CDP 的
   `Input.dispatchKeyEvent`,或先把文本放进剪贴板再 Ctrl+V。

## 三、CDP 踩坑备忘

- `Input.dispatchKeyEvent` 的合法 `type` 是 `keyDown` / `keyUp` / `rawKeyDown` / `char`,**没有 `keypress`**,传了会报 `-32602`。
- 光发 `keyDown` 不足以触发网站提交逻辑,要配 `char`(回车就是 `char` + `text: '\r'`),或直接点搜索按钮。
- 清空输入框用真键盘(`Backspace` 序列)比直接改 `value` 更接近真实行为,能触发站点的监听器。

## 四、坐标备忘

- **主显示器分辨率和 `pyautogui.size()` 未必相同**(后者在多显示器下是整个虚拟桌面)。
  按 pyautogui 坐标点击时要用它自己的坐标系,先打印 `pyautogui.size()` 再换算。
- pyautogui 默认 `FAILSAFE = True`:鼠标甩到屏幕左上角会中断脚本,建议保留。

## 五、典型用法

```powershell
# 1) 你先双击 tools\打开可控制浏览器.ps1(沙箱外启动)
# 2) 然后 agent 就能这样持续控制:
node -e "const r=await fetch('http://127.0.0.1:9222/json/list');const t=await r.json();console.log(t.filter(x=>x.type==='page').map(x=>x.title).join('\n'))"
```

```python
# 操作任意桌面程序
import pyautogui; pyautogui.click(700, 400); pyautogui.write('hello')
# 看屏幕
from PIL import ImageGrab; ImageGrab.grab().save('shot.png')
```

## 六、没验证的部分(如实说明)

- 没能实现"agent 自己冷启动一个浏览器然后跨命令持续控制"。**冷启动需要人在沙箱外做一次**,之后才全自动。
- 复杂 UI 的 OS 级盲点坐标点击容易点错,优先用 CDP / UI Automation 的结构化定位。
- 没有实测过游戏、带反作弊的程序、UAC 提权弹窗——这些大概率会被拦。

## 七、事故记录

搭建过程中的第一次尝试用 `Start-Process` 在沙箱内拉起 Chrome,导致**已打开的 4 个 Chrome 进程全部退出**(沙箱终止了进程组)。其中标签页靠 `--restore-last-session` 找回了部分。后续改为沙箱外启动才恢复正常。
教训:**不要在沙箱内反复尝试启动已有实例的浏览器。**
